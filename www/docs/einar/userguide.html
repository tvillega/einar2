Glossary

In Xen terminology dom0 is the physical computer and domU is a virtual computer

Virtual networking

Networking in Xen is rather complicated and a common source of confusion for developers but more about that in the advanced user guide.
This is how it works from the users point of view:
When a lab is started a number of virtual switches are created in dom0 that the domUs will connect to. domUs are newer connected directly to eachother, there is always a switch between them.
eth0 of domU is always connected to the switch xenbr0

User interface

Starting a lab

When the computer starts you will automatically reach the user interface as shown above.

To start a lab, simply click "start a lab". You will see a list of categories, click one one of them and you will se the names of all the labs in that category. Click on the lab you want to start and you will see a topology map. Click on "start lab" and the routers and computers will automatically start.

Stopping a lab

When the lab has started there is a link at the end of the page in Firefox that says "Stop lab", simply click it. There is no need to power down the virtual computers first.

If you loose the webpage the lab can be stopped from "running labs" on the homepage.

Creating a lab

Click "Create a lab" on the startpage and follow the dialog. You can create 16 virtual machines at most if you have enough memory. With 256MB of RAM, 8 virtual machines (routers and computers) is the max recommended, trying to start more might cause your computer to crash.

Your new lab will be reachable from from "start a lab" under the category "custom".

Saving a lab

Browse to your lab and click "save lab". The lab will be saved in /home/root/labs/, you can upload it by ftp from a dom0 terminal (see the Linux section below)

Importing a lab

First make sure you have internet connectivity. If you use DHCP, click "renew IP" from the startpage

Click on "start a lab" and then "import lab". Write a URL in the textfield and click submit. Your new lab will be accessible from "imported" under "create a lab"

Quagga

Quagga is very similar to IOS but there are some diefferences. I will only discuss the most importent commands, check the Quagga documentation for more info

Configure interfaces

When a routers starts you will be at the equivalent of an enable prompt on IOS

The interfaces are always named eth0, eth1 and eth2 (if 3 interfaces are specifyed).

Hello, this is Quagga (version 0.99.3).
Copyright 1996-2005 Kunihiro Ishiguro, et al.

router1# configure terminal
router1(config)# interface eth0
router1(config-if)# ip address 192.168.0.1/24
Commands can be abbreviated just as in IOS
router1(config-if)# exit
router1(config)# in eth1
router1(config-if)# ip add 192.168.1.1/24
It is only possible to have one loopback interface but it can have multiple ip addresses
router1(config)# interface lo
router1(config-if)# ip address 192.168.2.1/24
router1(config-if)# ip address 192.168.3.1/24

Configure routing protocols

There can only be one OSPF routing process so the process number is not entered
router1(config)# router ospf
router1(config-router)# network 192.168.0.0/24 area 0

Ethereal

Ethereal is a very powerfull open source network protocol analyzer.

For more information see the Ethereal website

Starting Ethereal

When you start a lab there will be a link "Start Ethereal" at the end of the page. It can also be started from the homepage

Capturing

Click on the top left icon, choose the interface you want to capture on and click OK.

To analyze the traffic between two routers you will capture on the switch that both routers are connected to. A virtual switch is also an interface in dom0. The switches in the preconfigured labs are named by the machines that are connected to it, e.g. the switch between router1 and router2 is named r1-r2

ifconfig

Setting the ip address:
ifconfig eth0 192.168.0.1 netmask 255.255.255.0 broadcast 192.168.0.255

route

Setting the default gateway:
route add default gw 192.168.0.1

lynx

There is a simple textbased webbrowser that can be used to test layer 7 connectivity between a virtual computer and a virtual webserver

lynx 192.168.01

To exit just press Q and answer Y
