Starting a lab maually

Creating a domain

Create a new domain and attach to it
xm create -c /einar/xen/einar-domU.cfg name=domU memory=11
xm is the tool to manage Xen domains. -c attaches a console to the new domU, name= sets the name and memory= sets the memory (in MB). The minumum memory required to boot a webserver is 6MB, minimum for a router is 11MB. The default is 12.
To leave the console, press ctrl+]. We don't know how to do this on swedish keyboard
To reconnect the console, first find the domain ID
xm list
and type
xm console <dom-ID>

Networking

In this example we will connect eth0 of domU to the physical network and eth1 to a virtual switch.
First create the switch
brctl addbr switch1
ifconfig switch1 up
then create the new domain
xm create -c /einar/xen/einar-domU.cfg name=domU vif=bridge=xenbr0 vif=bridge=switch1
xenbr0 is created on startup of dom0 and is attached to the physical eth0

Configuring domU

Kernel parameters can be passed to domU with the extra='' parameter to xm
xm create -c /einarc/xen/einar-domU.cfg name=domU vif=bridge=xenbr0 vif=bridge=switch1 extra='hostname=domU eth0=dhcp eth0bw=1mbit,10ms eth1=10.0.0.1/8 eth1bw=100mbit,100ms dhttp=yes vtysh=yes ospfd=yes bgpd=yes ripd=yes isisd=yes'
hostname=domU sets the hostname to domU, eth0=dhcp will use dhcp to set the ip of eth0,
eth0bw=1mit,10ms limits the outgoing bandwidth to 1Mbit and sets delay to 10ms,
eth1=10.0.0.1/8 sets the ip of eth1, dhttpd=yes starts the webserver,
vtysh=yes starts Quagga and it's interface, ospfd=yes configures quagga to start the ospf daemon.

The bw setting can be eth[0-2]bw=\d{1,6}[k|m]bit,\d{1,6}ms. Specifying 100mbit will not set bandwidth, only delay.
Sepcifying 0ms will not set delay, only bandwidth

The kernel parameters are read by /etc/rcS.d/S40hostname.sh, /etc/rcS.d/S41configquagga and /etc/rc2.d/S40setupifs in domU.

All or any of the extra= parameters can be omitted and configured manually after domU has started

Cleaning up

Destroy the started domain
xm destroy <dom-ID>
Remove the switch
ifconfig switch1 down
brctl delbr switch1
Clean up storage
for i in `seq 1 31`; do losetup -d /dev/loop$i; done
This will only remove unused loopback devices.

Remastering

These instructions are based on the Knoppix Remastering Howto at knoppix.net. The main difference is that we use grub so the boot image has to be stage2_eltorito.

In this example /dev/sda1 is used for storage, change it to whatever partition you are using.

Preparing

Boot from the live cd and mount the harddrive. The partition needs to be at least 3,2GB
mount /dev/sda1
Create a directory to work in
mkdir /mnt/sda1/knx
You will need up to 1GB of memory to do the compression. If you don't have that much RAM, use swap.
If you don't have enough memory the compressed KNOPPIX file will be smaller and it will not be possible to boot. You will not get any error message!
cd /mnt/sda1/knx
dd if=/dev/zero of=swapfile bs=1M count=750
mkswap swapfile
swapon swapfile
We will create two directories, source will contain the uncompressed files and master will contain the big compressed file and other things that need to be uncompressed.
mkdir -p /mnt/sda1/knx/master/KNOPPIX
mkdir -p /mnt/sda1/knx/source/KNOPPIX
Copy the files from the compressed filesystem (this will take some time)
cp -Rp /KNOPPIX/* /mnt/sda1/knx/source/KNOPPIX
Copy all files that will not be compressed (skipping the big compressed KNOPPIX file)
cd /cdrom && find . -size -200000k -type f -exec cp -p --parents '{}' /mnt/sda1/knx/master/ \;
Now you are ready to start customization. See the Knoppix Remastering Howto for more information about that

Creating the iso

Compress the contents of /mnt/sda1/knx/source to /mnt/sda1/knx/master/KNOPPIX
mkisofs -R -U -V "KNOPPIX.net filesystem" -publisher "KNOPPIX www.knoppix.net" \
-hide-rr-moved -cache-inodes -no-bak -pad /mnt/sda1/knx/source/KNOPPIX \
| nice -5 /usr/bin/create_compressed_fs - 65536 > /mnt/sda1/knx/master/KNOPPIX/KNOPPIX
Update the md5 hashes. This is used when giving the testcd kernel parameter to verify the cd
cd /mnt/sda1/knx/master
find -type f -not -name md5sums -not -name boot.cat -not -name isolinux.bin \
-exec md5sum '{}' \; > KNOPPIX/md5sums
Now create the iso file
mkisofs -pad -l -r -J -v -V "KNOPPIX" -no-emul-boot -boot-load-size 4 \
-boot-info-table -b boot/grub/stage2_eltorito -c boot/isolinux/boot.cat \
-hide-rr-moved -o /mnt/sda1/knx/einar.iso /mnt/sda1/knx/master
Your new iso is now in /mnt/sda1/knx/einar.iso

Script

I created a script that will create the ISO and copy it to an samba share. You must do the preparations above first. Use at own risk. 
#!/bin/bash
#==============================================================================
# Example script to remaster Einar.
# It takes one argument that will be part of the filename for the iso
#
# Anders Siverby 2006, siverby@kth.se
#=============================================================================
echo turning on swap
swapon /mnt/sda1/swapfile
echo renewing ip
pump
echo removing old .iso
rm -f /mnt/sda1/knx/einar*
echo compressing filesystem
mkisofs -R -U -V "KNOPPIX.net filesystem" -publisher "KNOPPIX www.knoppix.net" \
-hide-rr-moved -cache-inodes -no-bak -pad /mnt/sda1/knx/source/KNOPPIX \
| nice -5 /usr/bin/create_compressed_fs - 65536 > /mnt/sda1/knx/master/KNOPPIX/KNOPPIX
echo calculation checksum
cd /mnt/sda1/knx/master
find -type f -not -name md5sums -not -name boot.cat -not -name isolinux.bin \
   -exec md5sum '{}' \; > KNOPPIX/md5sums
echo creating iso
mkisofs -pad -l -r -J -v -V "KNOPPIX" -no-emul-boot -boot-load-size 4 \
	  -boot-info-table -b boot/grub/stage2_eltorito -c boot/isolinux/boot.cat \
		 -hide-rr-moved -o /mnt/sda1/knx/einar$1.iso /mnt/sda1/knx/master
echo connecting with smb
mkdir /mnt/knx
cp --reply=yes /usr/share/samba/smb.conf /etc/samba/smb.conf
mount -t smbfs -o username=johnsmith,password=fivebananas //192.168.222.1/knx /mnt/knx
echo copying to smb
cp /mnt/sda1/knx/einar$1.iso /mnt/knx/
echo Done.

Kernel customizing and Xen upgrading

Domain 0 and domain U run different kernels. Altough it is possible to create a kernel that will work within both domains, it is not a desirable solution. All the hardware support needed for domain 0 is useless and a waste of space and resources in domain U. The domain U kernel is further customized from default domain U config. Most stuff that is not explicitly needed is removed, while features like traffic shaping is added. The domain 0 is also a bit customized. Sound support and other unneccessary parts have been stripped to keep memory usage down.

Kernel configuration files are included in the CD[1][2] for future customization or upgrading purposes. Please note that these kernel and their config files are xen-patched version 2.6.15. If you upgrade to a later kernel, make sure to pay attention to any newly added kernel options/modules. Everything that is added to the kernel will make it's size increase, and with that, may render the kernel unbootable within the configured memory limits. Also note that you cannot use a standard kernel from kernel.org, you need the xen-patched sources[3][4].

Upgrading the domain 0 kernel

Kernel modules reside in their normal place, /lib/modules when running the CD. Altough, since this is a LiveCD system, some modules need to be accessible in an early startup phase. These modules are SCSI/SATA provide access to the device containing the Einar boot media. Additionally, cloop[5] (Compressed loopback filesystem) and unionfs[6] modules are needed here. These modules reside within the miniroot filesystem. The miniroot is a gzipped ext2 filesystem within a file, and is placed together with the domain 0 kernel[1]. To modify this filesystem, gunzip it and mount it. Remember to unmount and gzip again when done. If the kernel is renamed (typically due to new version), remember to update the bootloader config file.[7]

Upgrading the domain U kernel

Kernel modules (if any) reside within the domain U filesystem[8]. Remember to unmount when done. If the kernel is renamed (typically due to new version), remember to update the domain U virtual machine config file[9].

General note about loopback filesystems (filesystem within a file)

You mount a loopback filesystem like this: "mount -o loop einar-domU.img /path/to/something".
Also, it's a good idea to run fsck before mastering a CD if the filesystem has been altered. If you need to create a new, larger filesystem, remember to set it's options not to auto-check itself every n mounts/n days.

Kernel/Xen Hypervisor Version:

The current kernel (aswell as the xen hypervisor and applications itself) is taken from xen-unstable[3][4] as of 2006-02-03. At the time, the latest stable version of Xen (3.0.1) was bundled with kernel 2.6.12.6. With this kernel version, it seemed impossible to get a domain U running with less than 17 MB memory assigned.

Since the kernel used cannot be any older than the Xen hypervisor, we were forced to move up to xen-unstable. Next stable release of Xen is likely to include sources for a 2.6.15 or 2.6.16 kernel, but project deadline prevented us from waiting for this.
